# Карточки боевых юнитов

## Где настраивать

- `Assets/Prefabs/UI/Unit Details/Unit Description Card.prefab` — общая карточка для найма и наведения. Заголовок, описание, портрет, опыт, таблица и пояснения доступны в иерархии. В `UnitDescriptionView` задаются порядок строк, значки, локализационные ключи, скрытие нулевых значений и цвета.
- `Unit Stat Row.prefab` в той же папке — шаблон строки таблицы. Значение выровнено справа; фон чередуется. Цвет одноцветных значков настраивается в `UnitStatRowView`, ресурсные значки сохраняют свои цвета.
- Защита представлена одной строкой: щит и заголовок, затем физический урон, огонь, холод и магия со своими значками и процентами. `Defense Values` и ссылки `defenseCells` редактируются в шаблоне строки.
- `Unit Description Tooltip.prefab` — задержку задаёт `WorldMilitaryRosterItemView` на шаблоне бойца, размер и отступы — `UnitDescriptionTooltip`. Колесо мыши над иконкой бойца прокручивает таблицу. Тултип не перехватывает нажатия и скрывается при уходе мыши или удалении элемента.
- `Assets/Prefabs/Base/Fort Popup.prefab` и `Archery Range Popup.prefab` — окна найма высотой 832 Canvas units. В `Window` находятся редактируемые элементы; `CanvasWindowFit` уменьшает окно и оставляет сверху место для ресурсов. Затемнение остаётся полноэкранным. Крестик назначается прямой ссылкой `MilitaryTrainingView.closeButton`, без поиска по имени объекта.
- Пища в окнах найма находится слева: на одного бойца и на весь запас данного типа. Сумма равна количеству мечников или лучников: действующая экономика расходует одну ягоду на жителя в день. Сумма обновляется по событию изменения ресурсов. В одиночном тултипе остаётся расход на одного бойца.
- `Assets/Resources/UI/Unit Details/` — определения мечника, лучника и каталог. Для нового типа создайте `UnitDescriptionDefinition`, назначьте боевой префаб, ресурс, пищу, GlobalStats исследований и локализационные ключи; добавьте определение в каталог. Имена ресурсов каталога должны совпадать с `MilitaryProfile.type`.
- `Assets/Sprites/Ui/Unit Stats/` — одноцветные спрайты 16×16; импорт PPU 32, Point, без сжатия и mipmaps. На Canvas значки имеют размер 32×32. Подложки — существующий 9-slice из строительного тултипа.
- Переводы RU/EN: `Assets/Resources/Localization/Base Localization.asset`, ключи `unit.*`.

## Источники чисел

Карточка не хранит копии параметров баланса. Она читает GlobalStats и компоненты назначенного боевого префаба; для бойца на World — компоненты его живого экземпляра. Сохранённые опыт и процент здоровья берутся из того же `MilitaryProfile`, что используется войсками.

- Здоровье, урон, сопротивления и регенерация: `Health.Stats`, `EnemyVisuals.Stats` / `EnemyAI_Ranged.GetStats()`.
- Частота атак: `1 / базовый интервал` соответствующего AI с учётом уровня, в атаках за секунду. Отдельная строка интервала убрана. Например, 1,5 с соответствует 0,67 атаки/с, а на десятом уровне — 1,33 атаки/с. Разброс интервала и время анимации продолжают определяться боевой логикой.
- Скорость: текущая скорость движения живого экземпляра либо диапазон GlobalStats ± персональный разброс для ещё не призванного бойца.
- Лечение у портала: GlobalStats исследований; отступление и приоритет целей: текущие указы.
- Опыт за убийство/помощь: константы `MilitaryExperience`; новый день полностью лечит войска по существующим правилам.

В существующей боевой логике обнаружено различие: `EnemyMovement.FixedUpdate` использует `_finalSpeed`, тогда как `CurrentSpeed` дополнительно умножается на уровень и применяется при выходе/возвращении. Таблица показывает фактическую скорость обычного движения, без изменения баланса в рамках этой задачи.

## Проверка

Проверены значения двух типов новобранцев, раненого бойца 10-го уровня, повторное использование строк, наведение/выход мыши, прокрутка и обновление здоровья живого лучника. Проверки Play Mode выполнялись в отдельной временной сцене, без операций найма и записи тестовых бойцов в сохранение. Временная сцена удаляется после проверки, рабочей остаётся Base.

Для компактной версии дополнительно проверены реальные клики обоих крестиков с расположенной поверх окон панелью ресурсов и обновление расхода пищи при количестве войск 3, 5, 7 и 0. Перед временным изменением количества ресурсов сохранён исходный конверт сохранения; после проверки он восстановлен.

`UnitDescriptionSetup` — инструмент первоначальной сборки. Повторный запуск заново применяет базовую вёрстку; для обычной настройки меняйте префабы напрямую. `UnitDescriptionValidation` содержит редакторские проверки и захват превью.
